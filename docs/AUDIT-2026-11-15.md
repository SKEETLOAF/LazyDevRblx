## Defects found in V1.0 and corrected in V1.1

1. **Cancel-versus-permission race (important):** The six-frame capture's `sequenceCancel=false` assignment occurred *after* yielding to `RequestScreenshotPermissionAsync()`. A Cancel click during the permission prompt could be cleared after Roblox responded. The corrected flow arms cancellation before the prompt, checks again after the prompt and polls cancellation while waiting on asynchronous frame buffers. A static source-contract regression test catches reintroduction. **Still requires live Studio verification.**
2. **Invisible pixel activity (measurement correctness):** The changed-pixel metric compared raw RGB even if source/target alpha was zero. Fully transparent GIF pixels with different hidden RGB were incorrectly called visible motion. Changed fractions now use **premultiplied RGBA channels**. Node tests validate transparent versus opaque changes.

## Next safe functional step: visible-change cues

V1.1 exposes `motionEvidence` within existing `lazydev_read_reference`, `lazydev_read_sequence` and sequence comparison results:

- Earliest sampled transition changing at least **8%** of sampled visible pixels (candidate onset)
- Largest qualifying changed-pixel transition (candidate peak)
- First subsequent transition changing at most **2.5%** (possible quiet after peak)
- Observed sample-spacing minimum, maximum and mean; very limited evidence labels for short clips

These are deliberately not semantic states. Camera movement, temporary UI, light changes, background motion, compression, occlusion, or differing frame cadence can dominate the statistics. Zero-delay GIF frames do not produce fabricated change-per-second rates. No aesthetic grade or actual animation-source reconstruction is provided.

## Remaining release risks and next live test

- V0.4–V1.1 Studio UI and client interoperability remain mostly **untested in Roblox Studio**. Stop calling those workflows fully verified until a user executes them on an installed plugin.
- There is not yet an end-to-end loop that automatically aligns camera/subject and temporal events between reference GIFs and Studio captures.
- Script-review Undo/Redo was tested only in the original V0.3 flow; newer UI additions could theoretically affect installation even while Node tests pass.
- More robust Luau syntax/API validation in CI, plus actual Windows Studio camera/permission/cancel tests, would add more confidence than a new unverified feature.
- Media statistics and reference images can include private information when shared to the user's AI client; manual preview and consent remain required.

**This is a static/API/automated audit, not a full software security certification or a claim that Roblox Studio was operated during the audit.**
