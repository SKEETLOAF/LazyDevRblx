# Game design

Define the intended player fantasy, choices, feedback, learning curve, and measurable success/failure before adding features. Design affordances and trade-offs rather than using complexity as a substitute for depth. Preserve each game's established goals and avoid generic, universally imposed core loops.

For cross-disciplinary experiences, specify how gameplay, animation, VFX, SFX and HUD communicate the same state. Keep authority and tuning parameters distinct from presentation. Test edge cases, economy changes, accessibility and optional active/idle routes against the intended audience.

**Quality evidence:** representative player playtests, useful decision points, failure/recovery behavior, UI/visual feedback, balance telemetry when available. A script running without errors is not a quality gate, and a single personal test is not a statistically valid balance finding.

**References:** Roblox UI, server authority and performance docs, plus project-owned design references when shared.
